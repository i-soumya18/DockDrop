Privacy

Offline isn’t a feature.
It’s the product.

DockDrop has no internet permission. Your files go from your phone to your SSD. Nowhere else. Ever.

Android permissions

What DockDrop can and cannot do

This is the actual AndroidManifest.xml permission set. You can verify it yourself.

Permission Status Why
INTERNET ✕ Not declared No cloud. No analytics. No remote config. CI fails if this appears.
ACCESS_NETWORK_STATE ✕ Not declared Not needed. Not wanted. CI fails if this appears.
FOREGROUND_SERVICE ✓ Declared Required to keep the backup running while the screen is off. Type: dataSync. Only starts on your tap.
FOREGROUND_SERVICE_DATA_SYNC ✓ Declared The specific service type for data transfer. Declared in Play Console.
POST_NOTIFICATIONS ✓ Runtime-requested To show backup progress and “Tap to back up” notifications. Requested on first run; backup works without it.
USB_PERMISSION (runtime) ✓ Runtime-requested Android shows a system dialog: “Allow DockDrop to access USB device?” You grant it once per device.
SAF tree permissions ✓ Per-folder via picker Storage Access Framework. You pick each folder in the system folder picker. Android grants read/write access to that tree only.
READ_MEDIA_IMAGES / VIDEO ✕ Not declared Not needed. DockDrop uses SAF tree permissions instead, which are scoped to exactly the folders you grant.
MANAGE_EXTERNAL_STORAGE ✕ Not declared Not used in v1. DockDrop uses SAF only, which doesn’t require this broad permission.
READ_CONTACTS / CALL_LOG / SMS ✕ Not declared DockDrop doesn’t back up contacts, call logs, SMS, or app data. Never.

Verify yourself: Settings → Apps → DockDrop → Permissions

What DockDrop reads

Exactly what you grant.
Nothing more.

DockDrop uses Android’s Storage Access Framework (SAF). You open a system folder picker and select each source folder. DockDrop can only read files within those exact trees — not your entire storage, not system files, not other apps’ private data.

Folders DockDrop can back up (with your permission):

  • ✓ DCIM/Camera
  • ✓ Pictures/
  • ✓ Documents/
  • ✓ Android/media/com.whatsapp/WhatsApp/Media
  • ✕ WhatsApp chat databases (private app data — Android blocks this)
  • ✕ Any other app’s private data (Android/data/ — blocked by OS)
What DockDrop stores

On your SSD only.

DockDrop stores all data on the SSD you chose. The only thing stored on your phone is the Room database (an index of what’s been backed up, for fast diffing) and the persisted SAF tree permission URIs.

On your SSD, DockDrop creates:

DockDrop/
  .dockdrop/
    drive.json          ← drive ID, created date
    sets/<setId>/
      HEAD              ← current generation number
      manifest.N.ndjson ← file index (path, size, hash)
      manifest.N.sha256 ← manifest checksum
  <SetName>/
    <SourceFolder>/
      ...files as-is...
  _deleted/
    <SetName>/<date>/   ← kept deletions

No database files, no temp files, no hidden cloud sync. Everything is human-readable.

Enforcement

How we keep the promise

Offline-first isn’t just policy — it’s checked automatically on every build.

✓
CI manifest lint rule

Every GitHub Actions build runs a lint rule (A8 Quality Agent) that scans the merged manifest for INTERNET or ACCESS_NETWORK_STATE. If found, the build fails and cannot be merged.

✓
Open source

DockDrop is open source. You can read every line of code and the AndroidManifest.xml. The CI workflow is public. Trust, but verify.

✓
Verifiable on your device

Settings → Apps → DockDrop → Permissions. Android shows every permission the app has. No network access listed means no network access possible — the OS enforces it.

✓
Bundled assets, no runtime downloads

Fonts (Manrope, Inter, JetBrains Mono) are bundled in the APK. No remote config. No runtime font downloads. The app works exactly as reviewed — forever, without internet.
